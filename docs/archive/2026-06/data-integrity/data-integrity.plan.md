# Plan — data-integrity (스펙 §5 데이터 오염 정제)

> PDCA Phase: **Plan** · 생성 2026-06-14 · 접근: 일회성 마이그레이션 스크립트(MongoDB 직접 정제)

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 과거연도(2020·2021) checklist_items에 구조 오염이 집중 — 2020은 질문/설명이 한 필드에 병합(1,515건), 2021은 거의 전체 미분류(`classification=''` 1,231건), 구조화 설명 `blocks`는 전 문항 0건. 5년 이력 비교의 신뢰성을 훼손. |
| **Solution** | 백업·dry-run·롤백을 갖춘 **일회성 멱등 마이그레이션 스크립트**로 ① ∙ 기준 질문/설명 분리 ② 2026→최근클린연도 common_key 분류 백필 ③ description→blocks 구조화 적재. 프론트 `getDisplayData` "?" band-aid를 데이터 정합으로 대체. |
| **기능·UX 효과** | 5년 이력/연도별 비교에서 2020·2021 항목이 질문·설명·분류가 분리·정상 표시. 구조화 렌더(불릿/표) 활성화. 현재연도(2026) 데이터는 불변. |
| **핵심 가치** | 심사점검표 기준 데이터 정합성 회복 → year-diff 신뢰성·검색·표시 품질 향상. |

| 축 | 값 |
|---|---|
| **WHY** | 과거연도 데이터 오염이 5년 이력·연도별 비교의 신뢰성을 떨어뜨림. 2026 클린 데이터를 백필 소스로 활용 가능. |
| **WHO** | 인증심사 문항 관리자·심사위원(연도별 추적/이력 사용자). |

| **SUCCESS** | 2020 병합 잔여 0 · 2021 미분류 대폭 감소 · blocks 적재율 100% · 2026 불변 · 총 9,984 유지. |

## 1. 배경 / 실측 근거 (9,984 문항, 2020–2026)

| 증상 | 규모 | 연도 | 비고 |
|---|---|---|---|
| 병합추출(설명 빈값+질문 jam) | 1,521 | 2020(1,515)·소수 22~24 | `getDisplayData`가 "?"로 임시 분리 |
| 미분류 `classification=''` | 1,601 | 2021(1,231)·2020(369) | 2021은 1,250 중 1,231 |
| blocks 미적재 | 9,984 전체 0 | — | 구조화 렌더 휴면 |
| (참고) 답안마커 bleed | 12 | 2021·2025 | **이번 OUT** |

- 데이터 모델(flat, `checklist_items`): top-level `question/description/field_specific_description/blocks/classification(C/R/B/'')/score/na_available/common_key/year/area_code/sub_category`.
- `common_key` = 문항번호 끝 7자(중분류.일련번호 `NNN.NNN`, 예 `010.090`) — 연도 간 동일 문항 식별 키(백필 매칭에 사용).

## 2. 요구사항 (확정 결정 반영)

- **FR-1 (2020 분리)**: `description`이 비고 `question`에 `∙` 포함 시 — `∙` **첫 등장** 기준 분리. 질문=∙ 앞(trim), 설명=∙ 이후 전체. `∙` 없으면 **원본 보존**(미변경).
- **FR-2 (2021 분류 백필)**: `classification==''` 문항 — `common_key`로 **2026 우선 → 없으면 최근 클린연도(2025→2022) → 그래도 없으면 '' 유지**. 강제 추측 금지.
- **FR-3 (blocks 적재)**: **전 문항** `description`(FR-1 분리 후) → `blocks[]`(`text`/`bullet`, 표 패턴 시 `table`) 생성. `formatBlocks` 폴백 대체.
- **FR-4 (마이그레이션 툴)**: `scripts/lib/backup.js` 재사용 백업 → `--dry-run` 미리보기 → 실행 → `reports/`(gitignore) 변경 리포트. `rollback-items.js`로 복구.
- **FR-5 (멱등성)**: 재실행 시 0 변경(가드: 분리=desc빈값&∙있음, 백필=''만, blocks=결정적 재생성).
- **NFR**: 2026 등 클린연도 불변, 총 문항수 9,984 유지, 트랜잭션/배치 안전.

## 3. Success Criteria (Check 단계 검증 대상)

- **SC-1** 2020 병합 잔여 = **0** (desc 빈값 & question에 ∙ → 0). 증거: 마이그레이션 후 카운트.
- **SC-2** 2021 미분류 잔여 = 백필 후 최소화 + **2026 매칭률 리포트**(잔여 '' 사유 명시).
- **SC-3** blocks 적재 = description 보유 문항의 blocks 생성률 **100%**.
- **SC-4** 안전 = 백업 생성·dry-run·**멱등(재실행 0 변경)**·롤백 검증 통과.
- **SC-5** 회귀 무결성 = **2026 문항 불변**(샘플 해시 동일) + 총 9,984 유지.
- **SC-6** 프론트 검증 = 5년 이력에서 2020 `01.010.020` 등 질문/설명 분리 표시(브라우저 확인).

## 4. 범위 밖 (Out of Scope)

답안마커 bleed 12건(차기 사이클) · ETL 재파싱(pdf 원본) · 신규 연도 적재 · 프론트 band-aid 제거(분리 안정화 후 별도).
