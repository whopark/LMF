# BS-001 · PDF 구조 분석 → PG 테이블 content 적재

- Created: 2026-06-17
- **Providers**: fallback (orchestra `auto` 미설치 → claude judge 단독)
- Related: SPEC-DB-001 (Mongo→PG), `.autopus/specs/SPEC-DB-001/mapping.md`

## What / Why / Who / When

- **What**: `pdf/<연도> 심사점검표/*.pdf`(분야별 점검표)를 파싱해 PG 정규화 스키마
  (`item_content`/`checklist_item` 등)에 content를 적재하는 파이프라인.
- **Why**: Mongo `lab_accreditation` 데이터가 **drop**돼 SPEC-DB-001 ETL 소스가 없다. PDF가
  원천 source of truth → PDF→PG 직접 적재로 Mongo 의존을 제거하고 PG에 실데이터를 확보한다.
- **Who**: 단일 개발자(의원 내부 도구). SPEC-DB-001 PG 데이터 적재 목적.
- **When**: 지금. Phase 2(ETL Mongo→PG)가 소스 부재로 막혔으므로 그 대체 경로.

## 현황 자산
- 기존 Python 파서: `parse_pdf_2026.py`, `build_2026_final.py`, `etl_v9.py`,
  `import_to_mongodb.py`, `transform_and_upload.py`, `validate_etl.py`/`validate_golden.py`.
- 산출물 `pdf/checklist_items_flat_v2.json` (9,984문항, 11.5MB) — PDF가 이미 파싱된 정본.
- PG 스키마(Phase 1) + Mongo→PG 매핑(`mapping.md`) 존재.

## 아이디어 후보 + ICE

> Score = (Impact × Confidence × Ease) / 100

### A. `flat_v2.json` → PG 시드 로더 (PDF 재파싱 없음) — **추천**
이미 PDF에서 파싱된 `flat_v2.json`을 PG에 적재하는 Node(knex) 로더만 작성. `mapping.md`의
변환규칙(공유 dedup→item_content, ''→NULL, score 정규화, blocks→jsonb)을 코드화.
- Impact **9** (PG 실데이터 즉시 확보, SPEC-DB-001 unblock) · Confidence **9** (데이터 검증됨·구조 안정)
  · Ease **8** (단순 변환+dedup 적재). **Score = 6.48**
- 한계: 사용자 표현("PDF 구조 분석")과 달리 *이미 파싱된* JSON 사용. 편집·이력은 없음(어차피 소실).

### B. 기존 Python 파서 → PG 출력 어댑터
`parse_pdf_2026.py`/`build_2026_final.py`를 재사용하되 출력 타깃을 Mongo/JSON → PG(psycopg)로
교체. **실제 PDF 구조 분석**을 수행(사용자 의도 직결).
- Impact **8** · Confidence **7** (연도별 파서 편차·2026 전용 가능성) · Ease **6** (Python→PG 매핑).
  **Score = 3.36**

### C. 신규 구조 인식 PDF→PG 파서
`pymupdf4llm`로 PDF 구조(섹션/문항/표/배점)를 새로 분석해 PG로 직접 적재.
- Impact **9** · Confidence **6** (레이아웃 편차·표 파싱 난이도) · Ease **4** (PDF 파싱 fiddly·기존 파서 재작성).
  **Score = 2.16**
