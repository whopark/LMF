# Plan — subcategory-order (중분류 심사점검표 순서 정렬, 스펙 §1/§8)

> PDCA Plan · 2026-06-14 · 적용 단위: **전역 단일 순서** · 기준: **MMM(문항번호 중간 3자리) 백자리 → 10코드 분류**
> (Design 확정: **Option C — 93 노이즈 라벨을 10개 코드 분류로 통합**. PDF 헤딩 파싱은 불필요 — 권위 순서가 MMM에 인코딩됨.)

## Executive Summary
| 관점 | 내용 |
|---|---|
| **Problem** | 중분류(sub_category) 93종이 분야마다 `sub_category_order`가 제각각(예: `지원시설과 환경`=16/14/11/7…), 라벨도 비일관(near-dup `질관리 일반`/`정도관리 일반`, `허용 기준 설정`/`허용기준 설정`). 가나다 아닌 심사점검표 순서가 미보장. |
| **Solution** | **MMM 백자리 → 10개 코드 분류**(01 심사범위 … 10 검사실이전 + 11 제공서비스)로 통합. `sub_category`=코드 라벨, `sub_category_order`=코드 정수. 검사특이 ~80종은 `06 검사수행 및 장비운용`으로 흡수. 마이그레이션(백업/멱등) + 드롭다운 코드순 정렬. |
| **기능·UX 효과** | 대시보드 중분류 드롭다운·문항 정렬이 심사점검표 순서로 일관 표시(분야 무관 동일). |
| **핵심 가치** | 심사점검표 기준 정합성(§1/§8) — "중분류 순서는 가나다 아닌 점검표 순서". |

## Context Anchor
- **WHY** 심사점검표 순서 정합성(§1/§8) — 미싱·오정렬 중분류는 누락 버그·심사 혼선 유발.
- **WHO** 인증심사 문항 관리자·심사위원.
- **RISK** 라벨 정규화=sub_category 값 변경(near-dup 병합) → 데이터 변이. 전역 단일 order가 분야별 점검표 순서와 충돌 가능. 백업/dry-run/롤백 필수.
- **SUCCESS** 중분류 정렬=심사점검표 순서(가나다 아님), order 분야 무관 일관, 제공서비스 정위치, near-dup 병합.
- **SCOPE** IN: 전역 sub_category_order 재정의 + 라벨 정규화 + 프론트 정렬. OUT: 문항 내용/배점/분류 변경, 신규 중분류 생성(점검표에 없는 것).

## 1. 배경 / 실측 (2026, 중분류 93종)
> 아래는 문제 서술. **최종 접근은 §2/§3(Option C — MMM 10코드 통합)**; "PDF 재정의·dense-rank·공통 백본 슬롯" 등 일부 표현은 B 잔재로 무효.
- `sub_category_order` 분야별 비일관: `검사결과 보고`=[4,5,6]·`시약: 일반`=[6,3,5,4]·`지원시설과 환경`=8개 값.
- 사용자 제시 **공통 백본 10개**(05 오타 `일빈`→`일반기구`):
  1 심사범위 · 2 질관리:일반 · 3 질관리:검사단계 · 4 질관리:검사전후단계 · 5 일반기구 및 장비 · 6 검사수행 및 장비운용 · 7 인력 · 8 시설 및 환경 · 9 안전 · 10 검사실이전
- DB 라벨 불일치: 3·4·5·6·10번은 현 DB에 없음(검체처리/검사결과 보고/지원시설과 환경 등으로 분산) → **PDF 기준 재정의 필요**.
- 검사특이 중분류 ~83종(분야 1개씩, 예 `혈액응고검사`·`MALDI-TOF`). 제공서비스=order 99(맨뒤).
- near-dup: `해당 검사별 허용 기준 설정`(45)/`허용기준 설정`(256), `질관리 일반`(9)/`정도관리 일반`(30).

## 2. 요구사항 (Option C)
- **FR-1**: `sub_category`를 **10코드 분류 라벨**(`"NN 이름"`)로 통합. `sub_category_order`=코드 정수.
- **FR-2**: 코드 = **MMM 백자리**(item_number 기반·멱등). 엣지: 제공(비숫자)→11·005 기타→06·980→04.
- **FR-3**: 검사특이 ~80종은 `06 검사수행 및 장비운용`으로 흡수. 제공서비스=11(맨끝). 검사실이전(10)=2026 데이터 없음·코드 예약.
- **FR-4**: 프론트 중분류 드롭다운(Sidebar)·문항 정렬이 `sub_category_order`(코드) 따름(가나다 제거).
- **NFR**: 백업·dry-run·멱등·롤백(기존 인프라 재사용), 전 연도 동일 매핑(MMM 불변), 총 문항수 불변.

## 3. Success Criteria
- **SC-1** 분류당 `sub_category_order` distinct=1 · 분류 수 ≤ 11.
- **SC-2** 드롭다운 = 10코드 점검표 순서(01 심사범위 → … → 11 제공서비스), 가나다 아님.
- **SC-3** 안전 — 백업·dry-run·멱등(재실행 changed=0)·롤백·총수 불변.
- **SC-4** 엣지 — 제공서비스=11(끝)·기타=06·검사실이전(10) 예약·980=04.
- **SC-5** 프론트 검증 — Sidebar 중분류 드롭다운 코드 순서 표시.
- *(near-dup 라벨 병합은 10코드 통합으로 자동 해소 — 별도 SC 불요)*

## 4. 범위 밖
문항 내용/배점/분류 변경, 점검표에 없는 신규 중분류 생성, 연도별 상이 순서(전역 단일 전제).

## 5. 리스크 / 완화
| 리스크 | 완화 |
|---|---|
| 라벨 병합=데이터 변이 | PDF 기준 매핑표 확정 후 dry-run 검수 + 백업/롤백 |
| 전역 order vs 분야별 점검표 충돌 | 공통 백본 전역 고정, 검사특이는 비충돌 후순위 슬롯 |
| PDF 추출 부정확 | 추출 결과 vs DB 93종 교차검증, 미매핑은 보류(추측 금지) |
